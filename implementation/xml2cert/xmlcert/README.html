Validación y generación de informes PDF de eficiencia energética con xml2cert y xmlcheck

Las aplicaciones xml2cert y xmlcheck, desarrolladas por el equipo de Energética edificatoria de la Unidad de Calidad en la Construcción del Instituto de Ciencias de la Construcción Eduardo Torroja (IETcc-CSIC) permiten comprobar la validez y viabilidad de un informe de eficiencia energética del edificio en formato XML (v3.0) y, en el caso de xml2cert además generar un Informe de certificación energética en formato PDF.

El objetivo de los programas es su integración con las distintas herramientas reconocidas para la evaluación de la eficiencia energética de los edificios para mejorar la calidad de los datos de salida y el diagnóstico de los errores más frecuentes.

xml2cert

La aplicación xml2cert comprueba la validez y viabilidad de un Informe de eficiencia energética del edificio en formato XML (v3.0) y, en caso de ser viable, emite un informe PDF de Certificación de la eficiencia energética de los edificios.

Si el documento es válido (no solo viable), además se incrusta el archivo XML original en el PDF, salvo que se indique la opción --skip-xml-embedding.

Los avisos y errores del programa, así como la información sobre el proceso de ejecución del programa se almacenan en un archivo de registro .log.

Uso

El ejecutable xml2cert debe llamarse indicando la ruta del archivo .xml que se desea comprobar y generar su certificado energético y, opcionalmente, indicando el directorio de salida. Si se omite este último la salida se genera en la misma ubicación que el archivo XML de entrada.

Linux:

    xml2cert "ruta_hasta_el/archivo.xml" -o directorio_de_salida

Windows:

    xml2cert.exe "ruta_hasta_el/archivo.xml" -o directorio_de_salida

Salida de resultados

La ejecución del programa puede dar lugar a distintas salidas de datos, tanto de informes en formato PDF como registro de errores. Estas salidas se generan, bien en el directorio de salida indicado explícitamente al llamar al programa (opción -o) o, a falta de este, en el mismo directorio del XML de entrada.

El nombre de los informes en PDF coincide con el del archivo XML de entrada pero con extensión .pdf. El nombre del registro de actividad añade al nombre del archivo XML de entrada la extensión .log.

Caso Informe PDF
Archivo XML válido y completo Sí
Archivo XML válido pero incompleto por falta de medidas de mejora Sí - con marca de agua
Archivo XML no válido pero viable (solo faltan elementos) Sí - con marca de agua
Archivo XML no válido e inviable No

El archivo de registro de error incluye el detalle de los errores de validación detectados: fecha y hora, nivel de alerta (ERROR, WARN, INFO, DEBUG, TRACE) y mensaje generado.

Archivos incompletos y marcas de agua

En el caso de archivos incompletos pero que podrían llegar a ser válidos y completos mediante la incorporación de algunos elementos, se marca el PDF con una marca de agua para indicar que es necesario completar el documento para que este sea válido.

Igualmente, también se añade una marca de agua a aquellos archivos válidos pero que son incompletos debido a la necesidad de incorporar medidas de mejora. Estos archivos XML están pensados para usarse en combinación con otros generados a partir de un mismo caso base pero aplicando medidas de mejora para generar un XML completo usando herramientas adicionales que permita combinarlos para añadir al caso base los bloques correspondientes a las medidas de mejora, al estilo de la herramienta VisorXML (aunque esta herramienta todavía no procesa archivo XML 3.0).

Ejemplos de uso

A continuación de muestra cómo llamar al programa con algunos casos de ejemplo, algunos no válidos o incompletos. Estos ejemplos guardan sus resultados en directorio build.

En entornos Windows los ejemplos deben ejecutarse usando xml2cert.exe en lugar de xml2cert y puede usarse el archivo prueba.bat, incluido en la distribución del programa, para ejecutar secuencialmente esta misma batería de pruebas.

  1. Ejemplo de generación de certificado (válido y completo):

    Archivo con toda la información completa, formato de textos, etc.

    xml2cert -o build examples/Ejemplo30_Informe.xml

    Se genera el archivo ./build/Ejemplo30_Informe.pdf y un registro de error (.log) vacío al ser un archivo válido y completo.

  2. Ejemplo incompleto (no válido, incompleto):

    Archivo en el que se ha omitido un bloque obligatorio MedidasMejora y por tanto no es válido, aunque es viable al poder completarse en algún momento.

    xml2cert -o ./build examples/Ejemplo30_InformeBloqueMedidasBorrado.xml

    Se genera el archivo ./build/Ejemplo30_InformeBloqueMedidasBorrado.pdf con una marca de agua que indica que el informe en XML es incompleto, ya que falta un elemento obligatorio (MedidasMejora).

    El registro de errores ./build/Ejemplo30_InformeBloqueMedidasBorrado-errors.log indica los errores de validación encontrados y se pueden ver los elementos faltantes para obtener un informe válido (elemento MedidasMejora ausente).

  3. Ejemplo con medidas de ahorro pendientes de definición (válido e incompleto):

    Archivo con el bloque de medidas de ahorro que contiene la etiqueta especial MedidasPendientes, que indica que no se han añadido medidas de mejora para incorporarlas en un paso posterior por otra aplicación.

    xml2cert -o ./build examples/Ejemplo30_InformeMedidasPendientes.xml

    Se genera el archivo ./build/Ejemplo30_InformeMedidasPendientes.pdf con una marca de agua que indica que el informe en XML tiene pendiente la definición de sus Medidas de mejora.

    El archivo de registro de errores está vacío, puesto que el XML es válido, pero deberían completarse las medidas de mejora y generar un XML completo con otra aplicación para generar un documento válido y completo.

  4. Ejemplo con etiquetas opcionales omitidas (válido y completo)

    Archivo con el contenido mínimo exigido en el esquema XSD. Parte del informe de ejemplo inicial pero se omiten campos opcionales.

    xml2cert -o ./build examples/Ejemplo30_InformeReducidoYPorDefecto.xml

    Se genera el archivo ./build/Ejemplo30_InformeReducidoYPorDefecto.pdf.

    El registro de errores está vacío puesto que el certificado es válido y completo.

  5. Ejemplo con textos sin formato (válido y completo)

    Archivo en el que los campos de texto libre no tienen formato, solo texto plano. Parte del informe inicial pero simplifica el contenido de los campos de texto libre al no usar HTML para asignar formatos tipográficos.

    xml2cert -o ./build examples/Ejemplo30_InformeTextosSinCdata.xml

    Se genera el archivo ./build/Ejemplo30_InformeTextosSinCdata.pdf.

    El registro de errores está vacío puesto que el certificado es válido y completo.

  6. Ejemplo de archivo no válido (no válido, no viable)

    Archivo que no corresponde a un certificado válido y además tampoco es viable añadiendo nuevas etiquetas.

    xml2cert -o ./build examples/Ejemplo30_InformeInviable.xml

    No se emite un informe en PDF.

    Se genera el archivo ./build/Ejemplo30_InformeInviable.log con el detalle de los errores de validación.

  7. Ejemplo de archivo no válido (no válido, no viable)

    Archivo vacío que no corresponde a un certificado válido y además tampoco es viable añadiendo nuevas etiquetas.

    xml2cert -o ./build examples/Ejemplo30_Vacio.xml

    No se emite un informe en PDF.

    Se genera el archivo ./build/Ejemplo30_Vacio.log.

xmlcheck

La aplicación adicional xmlcheck permite comprobar la validez y viabilidad de informe XML, notificando en consola del resultado de las comprobaciones, sin generar un informe de certificación en PDF.

El objetivo de esta aplicación no es tanto la integración con otras herramientas sino como ayuda al diagnóstico y desarrollo, permitiendo el uso de distintos esquemas de validación.

Uso

La aplicación admite tres parámetros, dos de ellos opcionales:

  • xml_path - ruta al archivo que queremos comprobar
  • schema_path (opcional) - ruta al esquema de validación en formato RelaxNG Compacto. Si no se indica se usa la versión embebida en la aplicación.
  • jing_jar_path (opcional) - ruta a la librería jing.jar de validación. Si no se indica busca en ../bin/jing.jar

Ejemplo de uso y salida

Ejemplos con shell en Linux. Para uso en windows utilizar xmlcheck.exe en lugar de xmlcheck.

$ xmlcheck ../examples/Ejemplo30_InformeBloqueMedidasBorrado.xml
